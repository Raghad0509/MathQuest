# التحضير للمناقشة مع الدكتور (أسئلة وأجوبة)

استخدم هذه الإجابات القصيرة أثناء العرض.

## س1) لماذا اخترتم Django + DRF؟
لأنها توفر بناء API بسرعة، وتربط البيانات بشكل واضح، وفيها لوحة admin مفيدة للإدارة.

## س2) لماذا React Native + Expo؟
لأن نفس الكود يعمل على Android وiOS، وExpo يسهل البدء لمشروع طلابي.

## س3) أين يوجد منطق اللعبة الأساسي؟
في ملفات الخدمات:
- `backend/game/services.py`
- `backend/stats/services.py`
- `backend/achievements/services.py`

## س4) ما الفرق بين هذا المشروع وتطبيق Quiz عادي؟
هنا يوجد خريطة ومغامرة وعقبات وتقدم داخل المستوى. الرياضيات هي آلية فتح التقدم وليست كل التجربة.

## س5) كيف تُخزن البيانات؟
SQLite أثناء التطوير، مع إعداد جاهز للانتقال إلى PostgreSQL.

## س6) ماذا يحدث عند الإجابة الصحيحة؟
- زيادة النقاط
- زيادة عدد الإجابات الصحيحة
- تحديث تقدم العقبة
- التحقق من اكتمال المستوى

## س7) ماذا يحدث عند الإجابة الخاطئة؟
- زيادة عدد الأخطاء
- عرض رسالة تشجيعية وإعادة المحاولة

## س8) كيف يعمل نظام التلميح؟
API التلميح يخصم 5 نقاط ويزيل اختياراً خاطئاً واحداً.

## س9) كيف تعمل السلسلة اليومية؟
عند إنهاء مستوى في أيام متتالية تزيد قيمة السلسلة ويتم منح نقاط إضافية.

## س10) كيف تم تنفيذ mini boss؟
تم إضافة نوع عقبة `mini_boss`، وكل مستوى ينتهي بهذه العقبة.

## س11) لماذا استخدمتم مكونات reusable في الـ frontend؟
للحفاظ على تصميم موحد وتقليل تكرار الكود.

## س12) إذا سأل الدكتور عن تطوير مستقبلي، ماذا تقول؟
- تحسين توليد الأسئلة
- تحسين الرسومات والأنيميشن
- لوحة متابعة للمعلم
- تقارير للأهل
- توثيق دخول أقوى ونشر سحابي

## نص مختصر (60 ثانية) للعرض

"MathQuest هي لعبة مغامرة تعليمية على الموبايل للأطفال. اللاعب يختار بروفايل ثم يدخل خريطة كنز، ويتقدم في المستويات عبر حل ألغاز رياضية لفتح العقبات. التطبيق مبني بـ React Native + Expo، والـ backend مبني بـ Django REST Framework. منطق اللعبة مثل التقدم، النقاط، التلميحات، مكافأة السلسلة اليومية، والإنجازات موجود في طبقة services داخل الـ backend. قاعدة البيانات SQLite للتطوير مع جاهزية للانتقال إلى PostgreSQL. المعمارية منظمة وبسيطة، لذلك سهلة الفهم والشرح في المناقشة."
